# FIRRIS source-data handoff and source-bound analysis

The authoritative machine-readable catalogue is [`app/services/source_data/firris_catalogue.json`](../app/services/source_data/firris_catalogue.json). It names 22 source categories, formats, geometry/CRS and vertical-datum policy, physical unit, temporal mode, spatial-resolution policy, required record fields, survey indicator inventories, and compliance-row dependencies. These are **required external inputs**, not datasets supplied with NOVA. No observation, datum, class code, uncertainty value or licence is manufactured by this contract.

| Format | Categories | Source-specific contract |
| --- | --- | --- |
| GeoJSON, WGS84 | independent flood observations; historical flood events; river/drainage network; buildings; roads; critical infrastructure; economic assets; administrative boundaries | RFC 7946 FeatureCollection, category geometry and required properties, valid coordinate range, declared positional uncertainty |
| UTF-8 CSV, WGS84 coordinates or boundary join | rainfall stations; river-stage stations; river-discharge stations; hydraulic cross-sections; vulnerability indicators; community-capacity indicators | Exact header, typed records, timezone-aware observation time, valid quality flag; complete indicator inventory and declared units per spatial unit for surveys |
| Single-band GeoTIFF | water-surface elevation; terrain DEM; soil permeability; land cover; inundation time slice; population density; cropland fraction; livestock density | Declared EPSG CRS, resolution in CRS units, nodata, finite nonempty valid pixels, category-specific numeric domain; land-cover class scheme |

Upload a multipart `manifest` JSON string and `file` to `POST /api/v1/source-datasets/validate` to perform structural validation without persistence. `POST /api/v1/source-datasets` repeats all checks before storing immutable source bytes and a `Dataset` manifest. `GET /api/v1/source-datasets/catalogue` serves the versioned catalogue. Requests follow the existing BFF/session/CSRF proxy and require active NOVA membership, a contributor role, same-organization FIRRIS project and active FIRRIS entitlement. The internal API still requires its server-only secret. Storage paths never appear in the response.

Every manifest requires project ID, category, source ID, EPSG CRS, applicable vertical datum, category unit, timezone-aware start/end, WGS84 geographic coverage, raster resolution or vector/station positional uncertainty where applicable, QA assessment, licence/permitted use/redistribution, producer/custodian/source URI/acquisition method, uncertainty, and exact file SHA-256. Community/vulnerability survey manifests additionally declare a `spatial_unit_reference` for their boundary join; vulnerability manifests declare a reviewed benefit/cost direction for every indicator. The upload response says `structural_validation_only=true` and `analysis_ready=false`. Maximum source size is 100 MiB and maximum table/feature count is 100,000; reverse proxies should also bound multipart request size because multipart parsing occurs before endpoint byte checks.

Validation does **not** prove that a self-declared licence permits NOVA deployment, that a gauge was calibrated, that a vertical datum is correct, that flood labels are independent, that survey sampling is representative, or that raster pixel values have the claimed physical unit. A source custodian and domain reviewer must establish these facts. An OWNER/ADMIN must explicitly submit all six review attestations and evidence references to `POST /api/v1/source-datasets/{dataset_id}/approve`; `POST /api/v1/source-datasets/{dataset_id}/revoke` removes readiness. Both routes require live NOVA membership and same-project ownership. The worker re-reads protected bytes, revalidates checksum/structure and approval evidence, and compares source ID, checksum, version and review timestamp pinned at submission. Revoked, changed or cross-project data fail closed.

`GET /api/v1/analyses/source-bindings/contract` publishes exact source roles for Hazard, Exposure, Vulnerability, Flood Insecurity, Flood Risk and Community Resilience. `POST /api/v1/analyses/source-bindings/validate` checks approval, category, temporal and AOI coverage, CRS and vertical-datum compatibility, boundary references and raster alignment. Raster alignment supports explicit CRS reprojection with nearest-neighbour resampling, rejects finer-than-source target grids, requires full AOI coverage and records the transformation. No unobserved pixels are filled. `POST /api/v1/analyses/source-bound` submits the source-bound modules, including Risk with exactly three upstream Result IDs and an explicit projected target grid. Survey records join reviewed administrative boundaries by spatial-unit ID and run the existing entropy-weighted FIRRIS functions; protected GeoJSON, Task/Result and source lineage persist as before. No RF probability, AEP or H×E×V result can satisfy the Risk binding contract.

Hazard selects the specification's **Module 5 entropy-weighted eight-indicator formulation**, not the legacy fixed-weight FHI. Its five exact source roles are rainfall stations, terrain DEM, river/drainage network, land-cover raster and soil-permeability raster. The manifest must declare `observation_interval_hours` for rainfall millimetres to become mm/h and `land_cover_scheme` (`esa_worldcover` or `modis_lc_type1`) for the specification's fixed class scores. The request must declare a projected metre-based square-cell `target_grid` and `hazard_options.drainage_window_m`, the local spatial support for stream length / area. An OWNER/ADMIN must additionally attest `hydrologic_coverage_verified` and `dem_conditioning_verified` on the DEM with evidence references. The worker rejects missing review, source checksum changes, unobserved AOI cells, rainfall extrapolation outside the gauge convex hull, incomplete station cadence, incompatible periods/units/CRS, unscored land-cover classes, DEM gaps and hydrologically unsafe boundaries. It computes slope and D8 accumulation on the reviewed full DEM before AOI clipping; measures river distance and local drainage length in projected metres; and applies the unchanged `compute_hazard_index` directions/entropy weights. River-stage and historical discharge/event sources are **not predictors in this selected eight-indicator formula**; they remain separate validation/history dependencies, not invented Hazard inputs.

The worker persists Flood Hazard Index and eight contributing **normalized** indicator COGs, a preview PNG, legend, source/version/checksum/units/datum/time/weight/QA/uncertainty lineage, and summary/metadata/provenance/package exports. They are delivered only by the existing authorized Result endpoints. The synthetic engineering tests prove computation and access control, **not** real-data scientific validity. Real licensed station, DEM, river, land-cover and permeability sources, documented upstream DEM conditioning/coverage, review of the drainage window and projection distortion, plus independent flood observations for authoritative validation are still required before operational Hazard claims.

Exposure requires approved population-density, residential-building, road, school/hospital/power critical-infrastructure, cropland-fraction and livestock-density sources in the same FIRRIS project. A reviewed industrial/commercial economic-asset inventory is optional and, when supplied, contributes the seventh indicator. Building and critical-infrastructure manifests must declare `inventory_asset_types`; vector source approvals must attest `coverage_complete_verified` with evidence references. A completed, protected source-bound Hazard Result from the same project and AOI is mandatory. The request supplies its Result ID, a projected metric `target_grid`, and `exposure_options.hazard_min_level` (`moderate`, `high`, or `extreme`). The worker rechecks every source's approval/checksum and the Hazard Result's task, formula/source provenance, source approvals, version, period, units, georeferencing and artifact checksum. Upstream versions and checksums are pinned at submission. Missing categories, incomplete coverage, mismatched CRS/time/units, stale approval or altered bytes fail closed.

Exposure clips the selected Hazard **index class** to the AOI; this is not a measured flood extent. Continuous population/cropland/livestock rasters are area-averaged onto the reviewed grid without filling gaps. Asset geometries are reprojected and intersected with the selected class; unique building/asset IDs are counted once, while road segments contribute their actual intersection length. After projected clipping, WGS84 geodesic cell area and road length support people/km², animals/km², cropland-fraction and road-density calculations. The unchanged `compute_exposure_index` entropy formula uses six required indicators and the optional industrial/commercial indicator. The Result persists E and normalized-indicator COGs, clipped asset GeoJSON, classed preview/legend, per-cell CSV, PDF/Excel reports, a ZIP package, counts, weights, units, uncertainty and full source/upstream lineage. All downloads remain behind Result authorization. Counts are explicitly **estimates inside a Hazard-index zone**, not observed affected persons, inundated assets or monetary loss. Real licensed and independently audited asset inventories, hazard/impact validation, and review of within-cell density assumptions remain required.

Vulnerability uses an approved `vulnerability_indicators` CSV joined by `spatial_unit_id` to an approved `administrative_boundaries` GeoJSON in the same FIRRIS project. The manifest must include all 16 catalogue indicators, each unit, reviewed benefit/cost orientation and measurement-scale description, plus `missing_value_policy: reject`; dataset-level QA, licence, provenance, uncertainty and temporal coverage remain mandatory. Previously registered manifests lacking these fields are not grandfathered into science execution and require a new reviewed registration. The selected polygons must be non-overlapping and cover the entire AOI; every selected unit must have every indicator within the analysis period. No imputation or equal-weight fallback occurs. The worker rechecks source approval, bytes and pinned review before execution.

`app/services/source_data/vulnerability.py` runs the existing Entropy Weight Method separately on the social (population density, elderly, children, disability, education, poverty, health access, early warning, age dependency, water/sanitation), physical (housing quality, materials, infrastructure condition) and economic (income, livelihood and crop dependence) indicators, with the declared orientations. The resulting three subindices feed unchanged `compute_fvi`, which derives entropy weights at the domain level. Normalized observations, both levels of weights, entropy, class statistics, units/scales, source IDs/checksums, QA/uncertainty and processing provenance persist in the Result. A protected administrative-unit GeoJSON is the native GIS output; the PNG is only a geographic preview, **not** a measured raster. CSV/Excel/PDF/ZIP and all products use protected Result delivery. Source approval attests but does not independently establish the semantic correctness of survey scales, sample representativeness or authoritative FVI accuracy; real licensed surveys and domain validation remain required.

Flood Insecurity requires an approved `community_capacity_indicators` CSV, the same approved administrative-boundary version, and the ID of a completed, protected `source_bound_vulnerability` Result from the same FIRRIS project and AOI. The community manifest must declare all 16 CPC/EWE/KF/DRE/RC indicators, each unit and measurement scale, benefit orientation (higher means more capacity), `missing_value_policy: reject`, period, QA, licence, provenance and uncertainty. Older community manifests without these fields require re-registration and review. The FVI Result loader rechecks its completed task, exact formula/readiness provenance, current approval and checksum of both FVI sources, vector checksum/version, target period, complete spatial-unit scores and polygons matching the bound boundary. Source and upstream Result versions/checksums are pinned at submission and compared again in the worker; changed approvals, bytes or Result state fail closed.

`app/services/source_data/insecurity.py` uses unchanged `compute_capacity_subindex` for CPC (plans, training, evacuation, resources), EWE (timeliness, accuracy, accessibility), KF (awareness, experience, risk understanding), DRE (response speed, relief, coordination), and RC (economic, infrastructure, social recovery). Unchanged `compute_fii` then applies `1 − capacity` to those five scores and includes the verified FVI score as-is, with entropy-derived top-level weights. Missing observations, incomplete/gapped/overlapping spatial units, constant non-informative domains, mismatched periods and unapproved inputs are rejected. The protected Result includes the unit-level FII GeoJSON, geographic preview, five-class legend, normalized indicator and FII inputs, both levels of entropy weights, class area summaries, source/FVI lineage, uncertainty/QA, PDF/Excel/CSV and ZIP. The preview is not a measured raster. Synthetic engineering tests do not establish survey representativeness or independent authoritative FII accuracy; real licensed community observations and domain validation remain necessary.

Community Resilience uses the same approved community-capacity and matching administrative-boundary sources, without an upstream FVI Result. `app/services/source_data/resilience.py` requires all 16 benefit-oriented indicators, explicit units/scales and reject-on-missing policy, complete non-overlapping AOI units, valid time coverage and current readiness evidence. It calls unchanged `compute_capacity_subindex` for CPC/EWE/KF/DRE/RC, then unchanged `compute_cri` on the **direct** capacity scores with entropy-derived weights. It does not apply the Flood Insecurity inverse-capacity transform. The protected Result includes a spatial-unit CRI GeoJSON, geographic preview (not a measured raster), five-class legend, geodesic class areas, normalized indicators and domain inputs, both weight levels, source/checksum and QA/uncertainty provenance, plus PDF/Excel/CSV/ZIP. Synthetic tests prove the engineering path but not survey representativeness, reviewed scale validity or independent authoritative resilience accuracy; real licensed community observations and scientific validation remain necessary.

Flood Risk requires completed protected `source_bound_hazard`, `source_bound_exposure` and `source_bound_insecurity` Results from the same FIRRIS project/AOI, an analysis period identical across all three, and the exact projected metric H/E `target_grid`. `app/services/source_data/risk_results.py` rechecks completed tasks, source approvals/immutable manifests, artifact bytes/checksums/versions, formula provenance, H→E and FVI→FII lineage, CRS/resolution/nodata and Exposure's precise Hazard-index zone mask. At submission and worker execution, a digest of each Result's summary/provenance/artifact manifest is pinned. Its H/E raster grid is never resampled. The FII score is piecewise constant only over its reviewed administrative unit: `app/services/source_data/risk.py` assigns it to an AOI-clipped H/E cell only when that entire footprint belongs to exactly one verified unit. Crossing or uncovered cells fail closed; no categorical interpolation, silent upsampling or invented value is applied. The unchanged `compute_fri` evaluates **FRI = H × E × FII** only on valid Exposure-zone cells. No H×E×V, RF score or AEP enters this path.

The protected Risk Result persists a tiled FRI COG on the original projected grid, exact cell-footprint GeoJSON, classed preview/legend, WGS84 geodesic class areas, PDF/Excel/CSV/ZIP, source/upstream Result IDs/versions/checksums, period, CRS/horizontal datum, DEM vertical-datum provenance, QA and uncertainty. Nodata outside the source-bound Exposure zone is retained. This is a dimensionless **index** within a Hazard-index class, not annual flood probability, observed loss or independently validated risk. Mixed-unit cells remain unsupported until a domain-reviewed aggregation rule exists. Real licensed and independently validated H/E/FII inputs and observed risk outcomes are required before operational scientific claims.

`Dataset` persistence remains a source archive, not a computed FIRRIS Result. The current tests use synthetic fixtures only. Operational approval still requires real licensed datasets and documented human scientific review; passing software tests is not evidence of authoritative model accuracy.

Physical flood-map products M02–M04 have a separate source-bound path from the FIRRIS entropy-weighted Hazard Index. M02 requires approved water-surface elevation and DEM GeoTIFFs in metres on the **identical** projected metric grid, with the same declared vertical datum and complete AOI coverage. It applies unchanged `compute_flood_depth` (water surface minus terrain, with dry cells set to zero). M03 requires an approved nonnegative hydraulic-model velocity GeoTIFF in m/s, with model-run and validation references and an explicit administrator `hydraulic_model_verified` review; station discharge/cross-section records alone are not silently interpolated to a raster. M04 requires completed protected same-project/AOI M02 and M03 Results on the exact same grid and period. It rechecks source approval, source/Result checksums and versions, then calls unchanged `compute_hazard_index` for depth × velocity (m²/s). Its five within-result quantile classes are descriptive, **not** absolute safety thresholds or probability. None of these modules uses RF scores or AEP. Source-bound COG/preview/legend/metadata and PDF/Excel/CSV/ZIP delivery are protected; a preview is not an independently observed map. Real licensed hydraulic data, model calibration review and independent authoritative validation remain absent.

Production deployment must keep the artifact directory private and shared with workers, back it up together with PostGIS, set an Nginx multipart limit, and document retention/erasure for licensed data. No new database migration is needed because the existing `datasets` table provides the metadata and asset reference.

M05–M07 use a separate temporal source-bound path and do not reinterpret the FIRRIS Random Forest score. M05 accepts `year_YYYY` bindings for at least ten consecutive complete calendar years of approved `annual_inundation_observation` binary GeoTIFFs, each with a fixed reviewed event definition, explicit year, full-year coverage, current checksum and an administrator's documented complete-record attestation. The observed flooded-year count divided by complete years is an **empirical annual-event exceedance fraction** for that exact definition, not a fitted rare-event frequency curve. No result is produced from an RF score, an isolated SAR screening image, incomplete annual coverage or a mismatched grid. The Result retains yearly source lineage, record length, observation period, event definition, binomial standard-error estimate and protected AEP COG/reports.

M06 binds only that completed, protected M05 Result from the same project/AOI and exact period/grid. Submission and worker execution recheck its task, method, source approvals/checksums, artifact checksum, version and AOI footprint. `T = 1/AEP` yields years only on cells with a strictly positive defensible empirical AEP; a zero-observed-exceedance cell makes full-AOI return-period output unavailable, not an inferred infinite or known rare-event period. No RF or arbitrary probability Result is accepted.

M07 binds approved `inundation_time_slice` binary GeoTIFFs at explicitly declared, fixed hourly cadence, starting and ending with dry AOI observations. Every slice has a timestamp, the same projected CRS/grid and complete AOI coverage. Any missing slice, temporal gap, changing cadence or wet endpoint fails closed because the event would be censored. Duration in hours sums wet interval-start states multiplied by cadence; no interpolation or single-extent extrapolation occurs. The protected Result retains temporal resolution, gap/endpoint policies, source lineage, uncertainty, COG, preview and standard PDF/Excel/CSV/ZIP exports.

These paths have synthetic engineering fixtures only until licensed, independently reviewed annual-event histories and timestamped observations are registered and approved. The ten-year minimum is an admission rule, **not** a guarantee of precise AEP or defensible long return periods. Event detectability, observation gaps, nonstationarity, temporal resolution and independent authoritative accuracy require domain review before operational claims.

M08–M10 are the canonical source-bound map products already produced by the Exposure, Vulnerability and Risk modules, not the legacy caller-array map classifiers. M08's people/assets are **estimates intersecting a verified Hazard-index class**, never observed flood losses. M09 remains GeoJSON at reviewed survey-unit scale; rasterizing it would invent within-unit spatial detail. M10 retains the unchanged **H × E × FII** formula and exact H/E grid-cell to FII-unit assignment. Their protected products include source/Result checksum lineage, period, CRS/datum, QA, uncertainty and report/package exports. The Risk validator compares horizontal CRS datum and inherited DEM vertical datum separately.

M11 currently produces only a transparent **relative eight-indicator Hazard-composite reclassification** from a completed, protected, still-approved source-bound Hazard Result. It retains the approved predictor inventory, original normalization/orientation and entropy weights. It is not a newly fitted susceptibility model, an RF score, an AEP, or independent validation of flood tendency. A distinct susceptibility model and any use of historical flood evidence require an approved scientific method and real reviewed observations before this row can be marked complete.

M12 currently produces only **relative depth–velocity hazard zones** from completed, protected M02/M03 Results. The existing physical depth × velocity formula is unchanged. Five empirical within-AOI quintiles are recorded with their actual break values; they are not regulatory danger or safety thresholds. Duration, frequency, AEP, historical extent and exposure are not silently included. A reviewed multi-factor methodology, real calibrated hydraulic data and independent authoritative validation remain prerequisites for a complete zonation claim.
